# AGENTS.md – FiskalPro DPH

Guidance for AI agents (and human contributors) working in this repository.

---

## What This Codebase Does

`fiskalpro-dph` is a desktop CSV column-filter/export tool. It wraps an Angular 21 SPA inside a Neutralinojs 6.8.0 shell. There is no backend; all logic lives in the Angular frontend. Native OS features (file save dialog, persistent storage) are accessed through the `Neutralino` global injected at runtime.

## Repository Layout

```
fiskalpro-dph/
├── bin/                    # Neutralino binaries – do NOT modify
├── frontend/               # Angular SPA – all application code lives here
│   └── src/app/
│       ├── components/     # Reusable UI components
│       ├── pages/          # Route-level page components
│       ├── services/       # Angular services (business logic)
│       └── models/         # TypeScript interfaces / data models
├── www/                    # Angular build output – do NOT edit by hand
├── neutralino.config.json  # Neutralinojs runtime config
└── package.json            # Root npm scripts only
```

> **All frontend source changes go inside `frontend/src/`.** Never edit `www/` directly — it is generated by `ng build`.

## Development Commands

```bash
# Install frontend deps (run once, or after package.json changes)
cd frontend && npm install

# Angular dev server – runs in browser, Neutralino APIs not available
npm run dev            # → cd frontend && ng serve

# Full desktop app (requires Neutralinojs CLI: npm i -g @neutralinojs/neu)
npm run app:run        # → neu run

# Production build + launch
npm run start          # → ng build --configuration production && neu run

# Package desktop binaries for all platforms (output → dist/)
npm run package        # → ng build --configuration production && neu build
```

## Coding Conventions

### TypeScript / Angular

- **Strict mode is on** (`tsconfig.json`). No `any`, no `@ts-ignore`.
- Use Angular **signals** for local component state (see `activeStep = signal<number>(0)` in `MainPageComponent`).
- Use `inject()` instead of constructor injection.
- Services are `providedIn: 'root'` singletons.
- Components are **standalone** (no NgModules). Import PrimeNG modules directly in the component's `imports` array.
- Reactive state is managed with **`BehaviorSubject`** inside services; components subscribe via `async` pipe or signals.

### Neutralino / Browser Dual Mode

`SettingsService` and `saveExportedFile` check `typeof Neutralino !== 'undefined'` before calling native APIs, falling back to `localStorage` / browser download. **Maintain this dual-mode pattern** for any new native API usage.

The `Neutralino` global is declared via `declare const Neutralino: { ... }` at the top of `settings.service.ts`. Extend that declaration if you add new Neutralino API calls.

### Styling

- Global styles in `frontend/src/styles.scss`.
- Component-level styles in `.component.scss` files.
- PrimeNG theming via `@primeng/themes`.
- Prettier is configured (`.prettierrc`) — run `npx prettier --write .` before committing.

## Data Flow

```
User drops CSV
  → CsvLoaderComponent
  → CsvService.parseFile()          (PapaParse → CsvData)
  → MainPageComponent.onFileLoaded()
      → SettingsService.getLastUsedProfile()  (restore saved columns)
      → activeStep = 1

User configures columns
  → ColumnSelectorComponent
  → MainPageComponent.onColumnsChanged()
  → SettingsService.saveProfile()   (persist to Neutralino.storage / localStorage)

User exports
  → CsvService.exportToCsv()        (PapaParse unparse)
  → SettingsService.saveExportedFile()
      → Neutralino.os.showSaveDialog + Neutralino.filesystem.writeFile  (desktop)
      → Blob download link                                               (browser)
```

## What Agents Should NOT Do

- **Do not edit `www/`** — generated output, overwritten on every build.
- **Do not modify `bin/`** — pre-built Neutralinojs binaries, not part of the source.
- **Do not add `NgModule`s** — the project is fully standalone-component based.
- **Do not introduce new npm dependencies** without checking whether PrimeNG or Angular already covers the need.
- **Do not suppress TypeScript errors** (`as any`, `// @ts-ignore`, etc.).
- **Do not commit build artifacts** (`www/browser/`, `node_modules/`).

## Build Output

`ng build --configuration production` outputs to `www/browser/`. Neutralinojs reads from `/www/browser/` as configured in `neutralino.config.json` (`documentRoot` and `resourcesPath`).

The binary name for the packaged app is `fiskalpro-dph` (see `cli.binaryName` in `neutralino.config.json`).
